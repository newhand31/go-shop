# 平實口播規範（v1）

這份規範管「平實口播版」的口播、主張清單與 Short。它取代 [style-guide.md](style-guide.md) 的幽默文案；舊文案與 `docs/scripts/` 留著對照，不再更新。

目標有兩個。第一，人聽一次就懂。第二，AI 或任何人能逐句查證：口播說的每一件「這個 repo 是這樣」的事，都有一條主張和一個可以執行的檢查。

## 1. 句子

1. **一句一主張**。一句話只說一件事，一句不超過 30 個字。
2. **主詞寫明**。寫「`SetItem` 用 pipeline 送出兩個指令」，不寫「它會一次送出去」。
3. **數字寫全**。寫「期限是 7 天」「3 個方法」，不寫「一陣子」「幾個」。
4. **一物一名**。同一個東西整章用同一個名字。第一次出現的名詞用一句話定義。
5. **不用反話、比喻、諧音、反問**。這些句子無法逐句查證。
6. **不點名真人**，不評論其他創作者或公司。
7. **程式名詞照原文唸**：`CartStore`、`go build`。畫面與字幕用同一個寫法。

## 2. 什麼要有主張編號

| 口播內容 | 做法 |
|---|---|
| 這個 repo 的事實（檔案、函式、行為、測試結果） | 掛 `C<章>-<號>`，主張清單裡要有機器檢查 |
| 其他語言或框架的對照（C#、Java） | 掛 `X<章>-<號>`，每一種語言各附一個官方文件來源 |
| 事故情境（客服訊息、時刻、對話） | 不掛編號。第一句要說「事故情境是這樣」，並由一個測試或壓測重現，重現的那一句掛 `C` |
| 下一章預告 | 不掛編號。只說下一章的標題與事故情境，不說數字結論 |
| 串場句（「先看原因」「接著看修法」） | 不掛編號 |

口播不唸行號。行號只放在畫面上，由產線從 tag 的程式碼取出，不會寫錯。

終端機畫面的輸出要貼真的。畫面放不下時，明寫「畫面省略中間 N 行」。

## 3. 主張清單怎麼寫

格式見 [claims/README.md](claims/README.md)。寫的時候守這幾條：

1. **檢查不能比主張弱**。主張說「三個方法」，檢查就要對到三個方法，不能只查到型別名字。
2. **說「沒有」要查「沒有」**。用 `git grep -q` 加 `exit: nonzero`，或 `git cat-file -e` 加 `exit: nonzero`。
3. **說「改掉就壞」要真的改**。用 `edit` 改一處，再檢查編譯或測試失敗，並比對錯誤訊息。
4. **說「測試證明」要真的跑**。用 `run` 執行那一個測試，並比對 `--- PASS: <測試名>`。需要 Docker 的加 `requires: ["docker"]`。
5. **跨章比較**用 `git diff --quiet <前一個 tag> <這個 tag> -- <檔>` 或 `git grep -q -e <字> <tag> -- <檔>`。
6. 主張本文中英文各一句，意思相同。

寫完跑 `go run ./cmd/claimcheck docs/claims/chNN.json`，要全部 `PASS`（`reference` 顯示 `REF`）。

## 4. 長片的一章（5–7 分鐘）

四拍，順序固定：

1. **事故**：章名、對應的 tag、開始前的狀態、事故情境。
2. **原因**：為什麼會發生，指到程式碼。
3. **修法**：這一章加了什麼，一次講一個改動，每個改動配一段程式碼。
4. **證明**：哪個測試或壓測證明修好，以及怎麼自己跑 `make claims`。

結尾三句：這一章的三個重點、對應的 tag、下一章的標題。

## 5. Short（45 秒以內，直式 1080×1920）

三拍加導流：事故一句、原因一段、修法一段、證明一句，最後一句說「完整說明在長片第 N 章」。

- 5 到 7 段，全片口播約 150 個字。
- 程式碼畫面最多一個，不超過 6 行。
- 只用長片那一章已經有的主張編號，不新增主張。

## 6. 英文版

英文版照同一份主張清單重寫，不逐句直譯。規則 1 到 7 照用，每句不超過 20 個英文字。
