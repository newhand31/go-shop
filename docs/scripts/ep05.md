## 1:45 C# 會怎麼寫（為什麼在 Go 行不通）

【畫面】左邊 Visual Studio：`public interface ICartRepository { ... }`、`public class RedisCartRepository : ICartRepository`、`builder.Services.AddScoped<ICartRepository, RedisCartRepository>()`。

> C# 的朋友，這個下午你大概這樣做：
> 先寫一個 `ICartRepository`，再寫 `RedisCartRepository : ICartRepository`，最後在 `Program.cs` 註冊一行。
> Java 的朋友一模一樣：`interface CartRepository`、`class RedisCartRepository implements CartRepository`，然後 `@Repository` 貼上去。
> 注意順序：**先有介面，才有實作**；實作還得在簽名上老老實實宣告「我實作這個介面」。這個宣告，是一張**寫在實作那一邊的簽名單**。

> 好，這很合理。可是它有一個副作用：介面通常跟著實作一起放。`Repositories` 資料夾裡，一邊一個介面、一邊一個類別，而且介面常常有十個方法，因為它是照著「這個東西能做什麼」設計的，不是照著「誰要用它」。
> 結果呢？一個只需要「讀購物車」的程式，被迫依賴一個有十個方法的介面。測試要做假的，就得把十個方法全部實作一遍。你說，這個設計難道不吸引你嗎？

> Go 說：不用宣告。你有那幾個方法，你就滿足。好那我們來看。

## 3:45 第一段：誰要用，誰來定義介面

【畫面】`internal/service/cart.go` 最上面，圈出 `CartStore`。

```go
// CartStore is what the cart logic needs from storage...
type CartStore interface {
    Items(ctx context.Context, cartID string) (map[int]int, error)
    SetItem(ctx context.Context, cartID string, productID, quantity int) error
    RemoveItem(ctx context.Context, cartID string, productID int) error
}
```

> 看這個介面。它宣告在 `service` 套件裡，也就是**使用它的那一邊**，而且只有三個方法：購物車邏輯真的用到的三個。
> 這就是我們專案規則寫的：**interface 定義在使用端**。使用的人說「我需要這三件事」，誰能做這三件事，誰就能被放進來。

【畫面】`internal/repository/cart.go`，捲過整個檔案，圈出沒有任何 `implements`。

> 再看實作的那一邊：`repository.Carts`。你找一找，這個檔案裡，**沒有任何一個字提到 `CartStore`**。它是一個普通的結構，裡面有一個 Redis client，有三個方法，名字、參數、回傳值，碰巧跟 `CartStore` 對上。
> 它不知道誰會用它。它甚至不知道 `service` 套件存在。
> 這就是隱式 interface：**滿足介面，不需要簽名，只需要方法**。有點像 C# 的 `foreach` 靠 `GetEnumerator` 方法就能跑，不用宣告介面：不是先有一張合約再來簽，而是你手上剛好有合約要求的那幾項東西，你就是對的人。

【畫面】`cmd/api/main.go`，圈出那兩行 `var _ service.CartStore = (*repository.Carts)(nil)`。

> 那誰來檢查「對不對得上」？**兩邊相遇的那個地方**：`main`。我們放了兩行，每個接縫一行，像是 `var _ service.CartStore = (*repository.Carts)(nil)`。意思是：「編譯器，請你確認這個型別滿足那個介面。」
> 我把 `repository.Carts` 的 `RemoveItem` 刪掉，再編譯——紅字，`missing method RemoveItem`。沒有 `implements`，檢查一樣一個不少，只是從「宣告的人」換成「接線的人」。

## 6:00 第二段：Redis，把狀態搬出行程

【畫面】`internal/repository/cart.go` 的 `SetItem`；旁邊 `redis-cli` 看 `HGETALL cart:xxx`。

> 好，現在實作。購物車放 Redis，用的是 **hash**：key 是 `cart:` 加 session id，field 是商品編號，value 是數量。
> 為什麼用 hash，而不是把整個購物車序列化成一段 JSON 丟進去？因為加一件商品，只要動一個 field，不需要先讀出來、改完再整包寫回去。兩個分頁同時加不同的商品，也不會互相蓋掉。
> 寫入的時候，我們用 pipeline，把「寫 field」跟「重設七天過期」兩個指令，一次送出去。購物車放著不動，七天後 Redis 自己清掉；客人每加一件或改一次數量，期限就往後推。

> 然後是 session。第 4 集我們的 session 放在記憶體的 map 裡。現在換成 `session.Redis`：`Create` 用 `SET`，`Exists` 用 `EXPIRE`——存在就順便延長，不存在就回 false。
> 看一下 `main`：這一行，**`session.NewMemory` 換成 `session.NewRedis`**。`handler` 一行都沒改。為什麼？因為 `handler` 當初只宣告了「我需要 `Create` 跟 `Exists`」，兩個方法。記得第 4 集我說「等下一集你就知道」嗎？就是這個。
> 當然，這個設計我也用過：把 Redis 換成別的東西，要改的就只有 `main` 的那一行。可是你要記得——真的換之前，**不要**預先抽一堆介面。介面是在你**有第二個實作、或測試要做假的**時候才抽的，不是因為「也許之後會換」。

## 8:30 第三段：使用端的介面，讓測試變小

【畫面】`internal/service/cart_test.go`，`memCartStore`；旁邊 `internal/handler/cart_test.go` 的 `fakeCarts`。

> 還有一個好處，我最喜歡。測試要做假的 store 嗎？三個方法，二十行，一個 map。不需要 mock 框架，不需要產生器。
> `handler` 這一層也一樣：它只需要 `Carts` 的三個方法，我們寫一個 `fakeCarts`，裡面是幾行回傳值。想測「service 壞掉會不會洩漏內部訊息」？讓 `fakeCarts` 回一個錯誤，裡面塞一個內網 IP，然後檢查回應裡沒有那個 IP。
> 小介面，小的假物件，小的測試。這不是巧合，是**使用端定義**帶來的：介面長多大，由用的人說了算。

【畫面】`service.Catalog`：只有 `List`。`*ProductService` 被直接傳進 `NewCartService`。

> 再給你看一個漂亮的：購物車需要知道商品的名字跟價錢，所以它需要一個 `Catalog`，只有一個方法 `List`。我們直接把第 2 集寫好的 `ProductService` 傳進去——它從來不知道有 `Catalog` 這回事，它只是剛好有 `List`。
> 這就是為什麼 Go 的程式碼，常常可以「事後」被接起來，不需要回頭改舊的程式碼。

## 10:15 證明：換一台機器，購物車還在

【畫面】`internal/handler/cart_integration_test.go`，兩個測試的名字。

> 光說不練，是有旁白的投影片。我們寫了兩個整合測試，用 testcontainers 起一個真的 Redis。
> 第一個，重演事故：兩台 API，各自用**行程記憶體**存狀態，同一個瀏覽器（同一個 cookie jar）。在 A 放一件東西，A 看得到；換到 B，**購物車是空的**。這支測試通過，代表我們**重現了 bug**。
> 第二個，修好之後：同樣兩台 API，session 跟購物車都放 Redis。在 A 放兩樣、在 B 看到兩樣、在 B 刪掉一樣、回 A 看，只剩一樣。再換另一個瀏覽器：看不到別人的購物車。
> 還有 session 與購物車的過期，由同一個測試驗證：過期了就是過期了，session 每次使用、購物車每次寫入，都會把期限往後推。

【畫面】`go test -tags=integration ./...` 全綠；接著兩個終端機各一台 API，`curl -c jar -b jar` 在 8080 加購、在 8081 看購物車，內容都在。

> 我說：「他換過幾台機器？」客服說：「不知道。」

## 11:45 三點收尾

> 好，我們收一下。
> **第一**，Go 的 interface 是隱式的：方法對上就滿足，不用 `implements`。檢查沒有少，只是從「宣告」換成「相遇的地方」，也就是接線的 `main`。
> **第二**，interface 定義在使用端，而且要小：只列用到的方法。別為了「之後可能換」預先抽象；有第二個實作或測試需要替身，再抽。
> **第三**，狀態不要放在行程裡：session 跟購物車放進 Redis，用 hash 存購物車、用過期時間清掉沒人要的，handler 一行都不用改。
>
> 老闆的下一則訊息：「庫存只剩 1 件，我們賣出去 3 件。」
> 下一集：**超賣**。
