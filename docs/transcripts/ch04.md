## 這份逐字稿引用的主張

- **C4-1**　同一個 IP 對 `/products` 連續送 1000 個請求：限流器的桶子容量是 10、每秒補 5 個。通過的請求數不超過「容量加這段時間補的數量」，至少有容量那麼多，其餘回 429，而且每個 429 都帶 `Retry-After`。測試 `TestFloodFromOneIPIsMostlyRejected` 起真的 HTTP server，走真的 TCP 驗證。
- **C4-2**　tag `ep03` 的程式碼沒有限流，也沒有 session：`internal/handler/middleware.go`、`internal/platform/ratelimit/ratelimit.go`、`internal/platform/session/memory.go` 都不存在。這三個原始碼檔是這一章新增的。
- **C4-3**　`Recover`、`RateLimit`、`Session` 三個 middleware 的型別都是 `func(http.Handler) http.Handler`：收一個 handler，回傳一個 handler。`handler.New` 用 chi 的 `r.Use` 串起來，順序是 `RequestLog`、`Recover`，然後是呼叫端傳入的 middleware。測試 `TestChainOrder` 證明請求依序進去、回應依相反順序出來：`first in, second in, second out, first out`。
- **C4-4**　`RateLimit` 在限流器回報用完額度時，回 429 與 `api.Error`（code 是 `rate_limited`），加上 `Retry-After` 標頭，然後 `return`，不呼叫 `next`。`Retry-After` 的秒數無條件進位，最少是 1 秒。測試 `TestRateLimit` 的案例 `blocked`（0.3 秒進位成 1）與 `retry-after rounds up`（2.1 秒進位成 3）都通過。
- **C4-5**　限流的 key 是 `RemoteAddr` 用 `net.SplitHostPort` 取出的主機位址，不含埠號；程式碼沒有讀 `X-Forwarded-For` 標頭。測試 `TestRateLimit` 的案例 `allowed` 與 `ipv6 remote address` 檢查 key 不含埠號，案例 `x-forwarded-for is ignored` 送出不同的 `X-Forwarded-For`，限流器收到的 key 仍然是 `RemoteAddr` 的主機位址。
- **C4-6**　限流器是 token bucket：每個 key 一個桶子，桶子有容量上限；每次經過的時間乘以補充速率，補進令牌，但不超過容量；每次請求拿走 1 個令牌。`cmd/api/main.go` 設定每個 IP 每秒補 10 個、容量 20。測試 `TestAllow` 的 4 個案例都通過。
- **C4-7**　`Limiter` 用 `sync.Mutex` 保護存桶子的 map：`Allow` 一進來就 `Lock`，並用 `defer` 解鎖。測試 `TestLimiterHoldsUnderConcurrency` 用 20 個 goroutine、每個送 25 個請求，通過的數量沒有超過上限。
- **C4-8**　`sweep` 會刪掉閒置到桶子已經補滿的 key，沒有這一步，map 裡的桶子只增不減。時鐘是注入的：`Limiter` 有一個 `now` 函式欄位，測試用 `fakeClock` 手動往前撥，這個 tag 所有 `_test.go` 檔裡都沒有 `time.Sleep`。測試 `TestSweepDropsIdleKeys` 證明閒置的 key 被刪掉。
- **C4-9**　`cmd/api/main.go` 把 `RateLimit` 放在 `Session` 前面，所以被限流擋下的請求到不了 session store。測試 `TestFloodFromOneIPIsMostlyRejected` 數 `Create` 被呼叫幾次：建立的 session 數不超過通過的請求數。
- **C4-10**　session id 是 16 個位元組（128 位元）的隨機數，來自 `crypto/rand`，程式碼沒有用 `math/rand`。cookie 設 `HttpOnly` 與 `SameSite=Lax`。`Session` 用 `context.WithValue` 把 id 放進請求的 context，key 是不匯出的型別 `ctxKey`。測試 `TestSessionCookieSticks` 證明瀏覽器連續 3 次請求，只有第 1 次回應帶 `Set-Cookie`。
