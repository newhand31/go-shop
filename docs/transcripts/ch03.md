## 這份逐字稿引用的主張

- **C3-1**　tag `ep02` 的程式碼只有 `/healthz` 與 `/products` 兩條路由，沒有 API 契約檔 `api/openapi.yaml`。`internal/handler/handler.go` 出錯時呼叫 `http.Error` 回純文字，也沒有替換路由器預設的 404 與 405 回應。
- **C3-2**　路由器與生成程式碼的預設回應不是 JSON。在 tag `ep03` 把替換用的函式拿掉，`TestErrorResponsesShareOneShape` 就失敗：沒有自訂的 404 時，`Content-Type` 是 `text/plain; charset=utf-8`；沒有自訂的 405 時，`Content-Type` 是空的；沒有 `ErrorHandlerFunc` 時，路徑參數格式錯誤的回應也是 `text/plain; charset=utf-8`。
- **C3-3**　`api/openapi.yaml` 定義 `Error`，必填欄位是 `code` 與 `message`，選填欄位是 `field`。`/products` 與 `/products/{id}` 兩個操作的 `default` 回應，都指向同一個 `Error` 回應。說明文字寫著 client 依 `code` 判斷，不依 `message`。
- **C3-4**　`make api` 用固定版本 `v2.8.2` 的 `oapi-codegen`，讀 `api/openapi.yaml` 產生 `internal/api/api.gen.go`。產生的檔案有 `Error`、`Product` 與 `ServerInterface`，檔頭註解寫 `DO NOT EDIT`。`internal/handler/handler.go` 有一行 `var _ api.ServerInterface = (*server)(nil)`；把 `server` 的 `GetProduct` 方法改名後，`go build ./internal/handler` 失敗，錯誤訊息是 `missing method GetProduct`。
- **C3-5**　`internal/service/errors.go` 有一個哨兵錯誤 `ErrProductNotFound`，用 `errors.New` 建立；還有一個型別化錯誤 `ValidationError`，有 `Field` 與 `Message` 兩個欄位和一個 `Error` 方法。`ProductService.Get` 在 id 小於或等於 0 時回傳 `*ValidationError`。
- **C3-6**　`ProductService.Get` 的回傳值最後一項是 `error`。找不到商品時，它用 `fmt.Errorf("get product %d: %w", id, ErrProductNotFound)` 包裝。把 `%w` 改成 `%v` 後，`TestProductService_Get` 失敗，訊息是 `want errors.Is`。
- **C3-7**　`internal/handler/errors.go` 的 `writeError` 是 handler 錯誤與生成程式碼參數錯誤的出口；路由器的 404 與 405 不走這裡，由 `notFound` 與 `methodNotAllowed` 直接呼叫 `writeJSON`。它用 `errors.Is` 檢查 `ErrProductNotFound`，回 404 與 `product_not_found`；用 `errors.As` 取出 `*service.ValidationError` 與生成程式碼的三種參數錯誤，回 400 與 `invalid_request`，並把欄位名稱放進 `field`。測試 `TestErrorResponsesShareOneShape` 的 `id` 不是數字與 `id` 不是正數兩列，檢查狀態碼 400、`code` 是 `invalid_request`、`field` 是 `id`。把 `errors.Is` 換成 `==` 比較後，`TestErrorResponsesShareOneShape` 失敗，訊息是 `status = 500, want 404`。
- **C3-8**　`writeError` 遇到不認得的錯誤，把原因寫進 log，回給 client 的只有 `internal_error` 與 `internal error`。把回應訊息改成原始錯誤文字後，`TestErrorResponsesShareOneShape` 失敗，訊息是 `message leaks internals`。
- **C3-9**　tag `ep03` 的 `internal/handler` 套件沒有任何 `http.Error` 呼叫。`ListProducts` 與 `GetProduct` 出錯時都呼叫 `writeError`。路由器的 404 與 405 換成 `notFound` 與 `methodNotAllowed`，兩者回傳 `http.HandlerFunc`，寫出的 body 是 `api.Error` 的 JSON，並直接呼叫 `writeJSON`。生成程式碼的 `ErrorHandlerFunc` 也呼叫 `writeError`。

- **X3-1**（說明用對照，機器不檢查）　Go 的函式用最後一個回傳值 `error` 回報失敗，呼叫端自己檢查。C# 用 `throw` 丟出例外，由外層的 `catch` 或例外處理器接住。Java 的 checked exception 要在方法簽名用 `throws` 宣告，或在呼叫端接住。
