## [2026-11-24] 多語言計畫：同一份契約，多個後端與前端系列，全部排程、每系列先行章把關
- 選了: 以 OpenAPI 契約為唯一真相，另做 C#、Rust 後端系列與前端系列（共用篇＋React、Vue、Svelte、Angular），加對照特輯；各系列以自己的語言為主角。一個系列一個 repo，契約與契約測試另開一個 repo；go-shop 既有 tag 不動，前端缺的 API 在 main 新增一章。前端用 SSR 全端框架與 shadcn 家族元件。全部章節一次排進計畫、自動推進，同時最多兩條線；每個系列第 1 章是先行章，作者看過才放行其餘章；其餘章由機器把關（契約測試、主張清單、E2E）。新 repo 先私人，發佈時由作者轉公開；公開與上傳一律由作者決定。
- 否決: 全部放一個 monorepo（各系列的章 tag 會混在一起，也會打斷 go-shop 已公開的 tag）；每個系列做完都等作者點頭（介入次數多）；完全不設關卡（系統性問題會被複製到每一章）；前端用 SPA（不符合真實電商的 SEO 需求）；前端共用一份 Web Components UI（各框架沒有可教的內容）。
- 因為: 使用者 2026-11-24 要求「前端共用(TS+各大流行框架)後端有多版本(C#、RUST...)」「想要每個都有影片」，排程方式拍板「A，希望它自己跑、我少介入，沒有期限」，定位拍板「以各語言為主角」。正確性可由機器檢查，風格只能由人看，所以人只看先行章。
